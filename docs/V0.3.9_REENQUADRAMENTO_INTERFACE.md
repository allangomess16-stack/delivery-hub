# V0.3.9 — Reenquadramento da interface

A V0.3.8 permanece a baseline funcional homologada. Esta versão não altera as regras
aprovadas do scanner nem do recebedor; reorganiza a interface antes de novas expansões.

## O que mudou

- `src/interface/app.ts` deixou de concentrar gestão de cargas e fluxo completo de entrega.
- gestão de cargas foi movida para `controladores/controlador-admin-cargas.ts`;
- fluxo de entrega foi movido para `controladores/controlador-fluxo-entrega.ts`;
- estado visual ficou isolado em `nucleo/estado-ui.ts`;
- filtros, seleção e scroll do Admin são preservados durante re-renderizações;
- eventos de listas principais começaram a usar delegação;
- edição de endereço/região passou a abrir em Bottom Sheet, sem desmontar a lista;
- alteração de endereço/região atualiza somente o card afetado e o resumo de regiões;
- consultas de DOM novas são limitadas à raiz da tela, reduzindo acoplamento global.

## Regra de estado

Estado de UI não deve entrar no Firebase/IndexedDB operacional:

- filtro;
- scroll;
- seleção de cards;
- Bottom Sheet aberto;
- foco.

Esse estado pertence à sessão visual do aparelho.

## Regra de renderização

Re-renderização total continua válida para troca real de tela ou mudança estrutural ampla.
Uma alteração localizada deve preferir atualizar apenas o componente afetado.

Na V0.3.9, a edição de endereço/região já segue esse modelo.

## Bottom Sheet

O componente genérico inclui:

- fundo modal;
- foco inicial no primeiro campo útil;
- devolução de foco ao elemento que abriu;
- fechamento por ESC;
- confirmação antes de descartar alterações não salvas;
- `safe-area-inset-bottom` para mobile;
- conteúdo com rolagem própria sem mover a tela de fundo.

## Resultado estrutural

`app.ts` caiu de aproximadamente 1.117 para cerca de 590 linhas. A próxima expansão
funcional deve preferir novos controladores/casos de uso em vez de voltar a crescer o
orquestrador principal.

## Guardrails para as próximas versões

1. não adicionar regra de negócio em `interface/`;
2. não sincronizar estado visual;
3. não registrar um listener por item quando delegação resolver;
4. não reconstruir lista inteira para alteração simples de um card;
5. não expandir `app.ts` com módulos que possuam ciclo de vida próprio;
6. manter scanner e fluxo V0.3.8 como comportamento de regressão obrigatório.
