# V0.4.7.2 — roteiro do piloto Firebase

## Escopo

Validar uma carga ficticia entre dois clientes reais:

- Admin no computador;
- entregador no APK Android;
- REST no entregador e Realtime Database observado pelo Admin;
- Outbox local preservada durante perda de rede.

Este teste nao confirma baixa automatica na iMile. O contrato iMile 2.3.18
permanece congelado como pesquisa contextual `DEVICE_VALIDATED`.

## Preparacao

Execute:

```text
BAT\FIREBASE\09_PREPARAR_PILOTO_V047.bat
```

Se o primeiro assistente Firebase tiver parado informando
`firebase\firebase\database.rules.json` ou `../dist is outside of project
directory`, use o pacote corrigido. Extraia por cima da pasta atual para
preservar `firebase\projeto.local.env` e execute novamente o BAT indicado.
Escolha reutilizar o projeto existente; nao crie outro banco.

Se aparecer `apiKey nao encontrada`, execute
`BAT\FIREBASE\07_USAR_MODO_FIREBASE.bat`. O arquivo
`public\firebase-config.json` é local, não acompanha mais o ZIP e passa a ser
regenerado automaticamente pelos BATs de Admin, publicação e piloto.

Se a API de criação responder HTTP 400, confirme no Console Firebase em
`Authentication > Sign-in method` que `E-mail/senha` está ativo. O BAT 02
corrigido também republica esse provedor e exibe apenas o código seguro da
falha, sem registrar senha, token ou `apiKey`.

A Firebase CLI 15 usa `database:set --force`; versões anteriores do pacote que
mostrem `unknown option '--confirm'` devem ser substituídas antes de repetir o
bootstrap.

No Windows PowerShell 5, o perfil temporário é gravado em UTF-8 sem BOM e
validado antes do envio, evitando HTTP 400 por JSON inválido.

Depois instale `APK\DeliveryHub-Piloto-Firebase-v0.4.7.2.apk` e abra o Admin com
`BAT\01_SERVIDOR_LOCAL.bat`.

## Teste

1. Entre como Admin no computador.
2. Crie um perfil ficticio de entregador e sua conta de acesso.
3. Crie uma carga manual ficticia com um tracking de teste autorizado.
4. Publique a carga.
5. Entre no APK usando a conta do entregador.
6. Confirme que a carga apareceu somente para esse entregador. No entregador,
   cargas novas sao consultadas ao abrir ou atualizar o resumo, sem WebSocket.
7. Desative a conectividade do aparelho.
8. Registre uma entrega e confirme `AGUARDANDO SYNC`.
9. Feche e reabra o APK; confirme a permanencia da operacao.
10. Reative a conectividade e aguarde a sincronizacao.
11. Confirme `NO HUB` no entregador.
12. Confirme que o Admin recebeu em tempo real uma unica operacao pelo UUID.
13. Sincronize novamente e confirme que o UUID nao duplicou.

O botao manual ignora o backoff temporario, mas nunca reenvia operacoes
bloqueadas por erro permanente. Se o Hub ja possuir o mesmo UUID, a tentativa
e reconhecida como idempotente e a fila local e limpa.

## Resultado esperado

| Etapa | Aparelho | Admin |
|---|---|---|
| Carga publicada | Disponivel ao login correto | Publicada |
| Entrega offline | Fila local | Sem operacao nova |
| APK reiniciado | Mesma fila e UUID | Sem duplicidade |
| Rede restaurada | `NO HUB` | Uma operacao pelo UUID |

Use apenas carga e contas ficticias. Nao registre documento, foto, assinatura
ou GPS de pessoa real durante a homologacao.
