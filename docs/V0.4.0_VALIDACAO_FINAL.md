# V0.4.0 — validação final antes da homologação

## Validações concluídas

- `package.json` em `0.4.0`;
- 144 arquivos TypeScript verificados sem erro de sintaxe;
- verificação de tipos executada com stubs locais apenas para dependências externas indisponíveis no ambiente e sem erro interno do projeto;
- imports relativos verificados: nenhum caminho interno ausente;
- `firebase/database.rules.json` validado como JSON;
- simulação executável do Outbox confirmou:
  - conclusão offline permanece na fila;
  - nenhuma tentativa remota ocorre offline;
  - ao voltar online o mesmo UUID é processado e a fila é removida após aceite;
  - estado muda para `AGUARDANDO_INTEGRACAO`, não para confirmação da transportadora;
  - erro permanente fica `BLOQUEADO` e não entra em loop automático;
  - serialização Firebase remove `undefined`;
  - seleção de operação remota escolhe o UUID mais recente.

## Endurecimentos adicionados na revisão final

1. O Firebase passa a armazenar operações por UUID:

```text
operacoes/{entregadorId}/{cargaId}/{pacoteId}/{operacaoId}
```

Isso impede que uma retransmissão antiga sobrescreva uma operação nova do mesmo pacote.

2. Estado local ainda pertencente à Outbox tem prioridade sobre leitura remota antiga.

3. `ERRO_PERMANENTE` e `ACAO_MANUAL` ficam bloqueados na fila até revisão; não são reenviados a cada timer.

4. A sincronização automática fica escopada ao `entregadorId` autenticado, evitando processar a fila de outro entregador que tenha usado o mesmo aparelho.

5. Payloads são sanitizados na fronteira Firebase para remover propriedades `undefined`.

## Limites conhecidos da V0.4.0

- execução depois que o Android mata totalmente o processo ainda depende da próxima etapa nativa;
- fotos continuam armazenadas localmente; upload durável de evidências para nuvem será tratado em etapa específica;
- `AGUARDANDO_INTEGRACAO` significa apenas que o Hub recebeu a operação;
- nenhuma baixa real em J&T, Anjun ou iMile é realizada nesta homologação.

## Validação definitiva

O GitHub Actions continua sendo a validação definitiva do pacote completo, pois instala as dependências reais, executa `npm run validate`, `npm run test`, `npm run build` e compila o APK Android.
