# V0.2.2 — Compartilhamento local e gestão de perfis

## Problema corrigido

IndexedDB pertence ao navegador. Chrome, Edge, Firefox e o navegador do celular não compartilham o mesmo banco.

Na V0.2.2, `SERVIDOR_LOCAL.bat` executa um pequeno servidor Node local e os adaptadores de perfis/cargas usam a API do mesmo servidor. Assim, todos os navegadores que acessarem o mesmo endereço enxergam a mesma base.

Exemplo:

```text
PC Admin: http://localhost:5173
Celular:  http://192.168.x.x:5173
```

Ambos usam o mesmo arquivo local:

```text
%LOCALAPPDATA%\DeliveryHubDev\storage.json (Windows)
```

Esse servidor é somente para desenvolvimento e validação. Futuramente os mesmos contratos receberão adaptadores Firebase.

## Offline/cache

As gravações continuam sendo salvas primeiro no IndexedDB do navegador. Quando o servidor local está disponível, são replicadas para ele. Se o servidor estiver indisponível, a operação local não é perdida.

## Gestão de perfis

A área Admin agora permite:

- criar perfil;
- editar nome e aliases;
- ativar/desativar;
- excluir definitivamente perfil sem histórico de cargas.

Perfis com cargas registradas não podem ser apagados. Devem ser desativados para preservar histórico e referências.

## Importante

Perfil operacional e conta de login continuam separados. Nesta fase existe apenas o login de entregador de teste (`ENT-TESTE`). Quando Firebase Authentication entrar, um usuário autenticado será associado ao `entregadorId` sem alterar o domínio operacional.


Para zerar o ambiente de teste, execute `RESETAR_DADOS_SERVIDOR.bat`.
