# V0.2.1 — Identidade, Perfis e Separação de Cargas

## Objetivo

A planilha passa a ser importada somente pelo perfil ADMIN. Cada coluna é conciliada com um `PerfilEntregador` e, somente depois da conciliação, a carga é particionada por `entregadorId`.

## Regra principal

```text
Excel -> Conciliação -> PerfilEntregador -> CargaEntregador
```

O aplicativo do entregador não escolhe outro entregador. O login define `entregadorId` e o repositório busca somente cargas desse ID.

## Perfis

- `ADMIN`: importa e distribui cargas.
- `ENTREGADOR`: vê somente a própria carga.

O domínio utiliza `usuarioId`, não `firebaseUid`. No futuro, o adapter Firebase converte `user.uid` para `usuarioId`.

## Profile Matcher

O caso de uso `ConciliadorPerfisPlanilha` retorna:

- encontrados;
- desconhecidos;
- conflitos;
- inativos.

A distribuição só é liberada quando não existir nenhuma pendência.

A normalização remove acentos, espaços duplicados e diferença de caixa. Não há fuzzy matching automático.

## Persistência

Cargas e perfis deixaram de usar `localStorage`. A V0.2.1 utiliza IndexedDB por meio de um contrato simples de armazenamento. A sessão mock continua pequena no `localStorage` apenas para simular o Firebase Authentication.


Para testar a separação real, vincule uma coluna do Excel ao perfil `Entregador Teste`, distribua as cargas, saia do Admin e entre como entregador.

## Preparação para Firebase

A troca futura fica restrita à infraestrutura:

```text
AutenticacaoLocalAdapter -> AutenticacaoFirebaseAdapter
RepositorioCargaLocalAdapter -> RepositorioCargaFirebaseAdapter
```

Scanner, fotos e fluxo de entrega não precisam conhecer o provedor de autenticação.

## Injeção de dependência

A composição concreta fica em `src/configuracao/composicao-local.ts`. A interface recebe `DependenciasAplicacao` e não instancia autenticação, banco ou repositórios diretamente.

No futuro, a composição Firebase poderá substituir apenas os adapters externos.
