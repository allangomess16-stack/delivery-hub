# V0.3.0 — Firebase Authentication + Realtime Database + Hosting

## Objetivo

Eliminar a dependência de PC e celular estarem na mesma rede.

## Arquitetura

```text
ADMIN
  │
  ├─ importa / organiza / publica carga
  │
  ▼
Firebase Realtime Database
  ▲
  │
ENTREGADOR
  │
  └─ login Firebase Authentication
```

## Separação de segurança

- `usuarios/{uid}`: identidade e papel.
- `dados/profiles/couriers/{entregadorId}`: perfil operacional.
- `dados/profile-links`: associações de colunas Excel (Admin).
- `cargas/{entregadorId}`: carga oficial; somente Admin grava.
- `operacoes/{entregadorId}`: progresso do entregador.
- fotos continuam locais nesta fase.

O entregador lê apenas o seu `entregadorId`.

A carga oficial e a operação foram separadas propositalmente para o motorista
não precisar de permissão para alterar a atribuição oficial da carga.

## Realtime Database location

O Realtime Database atualmente oferece `us-central1`, `europe-west1` e
`asia-southeast1`. Para operação no Brasil, o assistente recomenda `us-central1`.
A primeira instância é criada pelo fluxo oficial `firebase init database`.

A localização não pode ser alterada depois que a instância é criada.

## Authentication

O arquivo `firebase.json` da raiz ativa:

```json
"emailPassword": true
```

O primeiro Admin é criado pelo BAT de bootstrap.

Contas que existam no Firebase Authentication mas não tenham um registro ativo
em `/usuarios/{uid}` não recebem acesso às cargas.

## Deploy

Primeiro uso:

```text
BAT/FIREBASE/01_CRIAR_E_CONFIGURAR.bat
```

Atualizações:

```text
BAT/FIREBASE/03_SUBIR_ATUALIZACAO.bat
```

## Limites desta fase

1. Fotos/POD ainda não são enviadas para Cloud Storage.
2. Escritas offline ficam no cache local, mas a fila idempotente/retry robusta é
   a próxima etapa.
3. Alterar email/senha de outra conta Firebase pelo navegador do Admin não é
   permitido; a criação funciona, mas gestão administrativa completa de
   credenciais exigirá backend privilegiado.
4. Exclusão de uma conta no Admin remove seu acesso no banco, mas a remoção
   definitiva do usuário no Firebase Auth será feita pelo backend administrativo.
